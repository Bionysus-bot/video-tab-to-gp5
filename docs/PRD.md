# 视频 / PDF 转 Guitar Pro 产品需求文档

文档版本：1.0  
日期：2026-10-23  
状态：需求已对齐；本文记录产品目标与后续规划，不代表功能均已实现。  
现有代码基线：`v0.2.0-preview.1`，试用分支 `codex/combined-tab-wip`。

## 1. 产品定位

面向个人本机使用的辅助转谱工具：用户导入带有动态谱面的视频或已有 PDF，选择谱面区域和类型，程序自动整理谱面、识别音符与节奏、复核疑点，并生成可用 Guitar Pro 打开和编辑的 GP5 草稿。

近期先做好 Windows 本机体验，再降低其他用户的安装门槛。下一阶段的首要目标是减少人工校对和操作步骤，识谱准确性是自动化的约束；速度优化服务于这一目标。

## 2. 已与用户确认的决策

| 项目 | 已确认要求 |
| --- | --- |
| 文档范围 | 整理整个项目的需求与后续规划 |
| 近期用户 | 先满足自己本机使用，再方便他人安装 |
| 第一阶段乐器 | 四弦贝斯 |
| 谱面类型 | 纯 TAB、五线谱＋TAB，两种流程分别保留 |
| 默认流程 | 先选择谱面区域和类型，再自动识谱生成草稿 |
| 优先方向 | 更自动化，减少人工校对和操作步骤 |
| 疑点处理 | 优先生成可下载草稿，明确标记具体疑点 |
| 界面 | 简洁、有设计感、低饱和；准备、处理、结果分区，避免全部挤在单列；说明与设置按需打开 |
| 数据保护 | 保留人工修改，保留旧版本与回退能力 |
| 来源与使用 | 标注上游来源、后续新增功能、非商业使用范围及版权说明 |

输出先采用现有 `.gp5` 格式；新版 `.gp` 和旧版 `.gtp` 不属于本阶段交付承诺。

## 3. 用户问题与产品目标

当前用户需要多次进行谱行整理、结构修复、原视频补读、模型复核和导出，且难以从大量告警中区分真正需要处理的问题。清楚的数字也可能因音符关联、符尾或边界判断失败而无法进入结果。笼统的低置信度又会增加重复核对。

本阶段期望的结果：

1. 一次确认区域和谱面类型后，主要处理流程自动执行，无需逐项点击修复按钮。
2. 先获得可下载草稿，不因普通低置信度或少量未确定内容阻断整曲导出。
3. 只处理有证据支持的修改；无法确定的内容保留明确疑点，不编造音符凑拍数。
4. 人工只需集中查看具体问题，能够直接对照来源图片。
5. 重试、刷新、重启、重新识别和升级时，不丢失已保存结果及人工修改。

## 4. 范围与边界

### 4.1 本阶段覆盖

- 本地视频及已有 PDF；继续复用项目保留的截图，不强制重新抽帧。
- 四弦贝斯纯 TAB、五线谱＋TAB；一个目标声部 / 音轨优先。
- 弦号、品位、时值、休止、附点、延音线、闷音；其他演奏法保留现有能力，不能可靠读取时提示。
- 跨行拼接、重复画面去重、印刷小节编号对应、左右边缘片段保留。
- 本地识谱、可选的局部视觉模型复核、可编辑结构化结果、GP5 草稿。
- 以 Windows 本机浏览器界面为首要运行方式。

### 4.2 本阶段不承诺

- 从声音转录音符、无 TAB 的纯五线谱、手写谱、任意复杂排版或多轨合奏自动转谱。
- 六弦吉他、五弦 / 六弦贝斯等新增乐器的完整验证；不主动移除已有兼容能力。
- 新版 `.gp` / 旧版 `.gtp` 的直接写出、手机应用、云端账号和协作系统。
- 自动导入用户在 Guitar Pro 内修改后的文件并合并差异。
- 对任意输入保证完整转谱或零错误。

特殊调弦、速度和拍号可由用户在设置中确认。谱面没有明确给出的信息不能声称已识别；默认值应标注为默认 / 待确认。

## 5. 现状与缺口

以下是现有版本的能力基线，不等于已达到后文验收标准。

| 能力 | 现有情况 | 下一步缺口 |
| --- | --- | --- |
| 视频处理与 PDF | 已有上传、框选、抽帧、去重、PDF 输出 | 减少重复操作，明确输入来源和缓存状态 |
| 区域选择 | 已优化拖拽，支持坐标和宽高调整 | 保持顺畅，与自动流程统一 |
| 两类谱面 | 原纯 TAB 与独立联合谱流程均保留 | 防止切换类型时误用旧结果 |
| 联合谱读取 | 已有音符头、符干、横梁与 TAB 关联 | 继续处理延音、两位数品位及遮挡边界 |
| 结构与补读 | 已有跨行处理及独立原视频补读草稿 | 自动串联，控制尝试次数，保留证据 |
| 局部模型复核 | 已有逐拍修改能力，效果依赖模型与输入 | 自动选择疑点、控制修改范围、明确失败退路 |
| 疑点表达 | 已有逐拍证据与针对性标记 | 统一分类、来源定位和处理入口 |
| 导出 | 已有常规、诊断及补读草稿等入口 | 汇总成清晰的默认草稿下载入口 |
| 校对界面 | 默认折叠，一次选择一个小节 | 增加按问题导航，避免要求逐小节确认 |
| 保存与版本 | 已有本地结果、备份和代码版本 | 明确任务快照与人工修改保护规则 |

现有样例曾从原视频补回 27 个占位小节，得到 170 小节、零占位的机器草稿。用户核对后仍发现延音线、两位数品位和局部节奏错误，并已手动修改。因此“零占位”“拍数通过”和“用户确认正确”必须分别记录，不能混为一个成功指标。

## 6. 默认使用流程

1. **导入**：选择视频或 PDF，显示文件与项目名称；允许继续已有项目。
2. **确认输入**：选择纯 TAB / 五线谱＋TAB，框选谱面区域；联合谱的区域应包含上方节奏和下方 TAB。PDF 以页面或谱行预览完成区域确认。
3. **自动处理**：整理与去重 → 结构对应 → 音符 / 节奏读取 → 校验 → 必要的补读和局部复核 → 生成草稿。
4. **获取结果**：显示草稿下载按钮及结果摘要，包括已识别、待确认和缺失内容。自动复核不能无限阻止草稿可用。
5. **按需处理疑点**：打开疑点列表，直接跳到对应拍位及来源图；修改后保存并重新导出。

用户无须先把所有小节标记为“已核对”才能下载草稿。没有原视频的 PDF 项目跳过视频补读；没有配置模型时继续使用本地流程。

## 7. 功能需求与验收

优先级：P0 为下一阶段必需，P1 为随后完善，P2 为后续扩展。

### F01 输入、区域和类型（P0）

- 视频、PDF 入口明确；保留来源文件和未经覆盖的原始截图。
- 框选区域支持拖拽及 X / Y / 宽 / 高数值微调，坐标以原图像素为准。
- 类型选择决定识别流程；类型或区域变化后标明旧结果来源，不静默复用不兼容缓存。
- 黑屏、片尾、重复帧和无谱内容自动过滤，但保留被过滤项及恢复入口。

**验收**：同一输入可分别进入两种读取流程；数值调整与预览一致；被误过滤谱行可恢复；改变类型不会把旧类型结果当成新结果。

### F02 谱行、小节与来源对应（P0）

- 分别保存画面顺序、印刷小节号和内部唯一标识，不单凭模型输出的编号覆盖对应关系。
- 行末、行首的部分小节保留为片段，结合相邻页面或视频帧拼接、去重。
- 每个结果能追溯至 PDF 页 / 谱行或视频时间及截图，拼接结果保留全部相关来源。
- 不能确认的重叠、缺口或编号冲突显式提示，不直接删除或强行拼接。

**验收**：跨行样例拼接后无重复音；编号冲突能定位来源；缺失片段仍可见；已确认内容不因边缘不完整而整段丢弃。

### F03 音符与节奏读取（P0）

- 纯 TAB 沿用独立流程；联合谱分别读取 TAB 品位与上方节奏，再在小节内按顺序及位置建立关联。
- 结合音符头、符干、整组横梁判断时值，避免为每个数字单独寻找最近竖线。
- 两位数品位、括号延续音、延音线和休止符分别处理；不能将被遮挡或缺失的音符直接认作休止符。
- 整小节拍数不符时保留确定拍位，将总拍数错误与具体不确定拍位分开表达。

**验收**：回归样例覆盖八分 / 十六分、两位数品位、跨小节延音、真实休止及半个音符被截断；一个时值错误不会把整个小节全部改成未知。

### F04 自动补读与局部复核（P0）

- 对结构缺口和具体音高 / 时值疑点自动选择补读路径；有原视频时优先寻找同小节的其他完整画面。
- 模型输入包含局部放大图、完整小节、必要上下文和明确问题，只接受允许字段的修改。
- 模型输出须经过弦号、品位范围、结构、节奏及来源一致性检查；不因总拍数恰好正确就接受修改。
- 保留每次候选、修改前后值、接受 / 拒绝原因及来源；支持回退。
- 设置有限重试和超时；无改善、模型不可用或结果不合法时结束复核，保留已有结果与疑点。
- 模型采用可选配置；优先支持已使用的 Ollama 非思考视觉模型，也保留兼容图片接口的配置能力。

**验收**：从一次“开始识谱”可自动进入必要补读 / 复核；无模型配置、超时或无效输出均不清空已有音符、不无限等待，并能生成已有可用结果的草稿。

### F05 疑点及置信度（P0）

- 区分：音高疑点、时值疑点、延音 / 演奏法疑点、结构缺口、编号冲突、信息待确认和普通 OCR 提醒。
- 疑点定位到小节和具体拍位；结构问题定位到相应片段。展示原因、候选与原图，而非只有分数。
- 原始 OCR 分数属于识别证据，不直接解释为音符正确概率。
- 获得其他证据后更新疑点状态；低分本身不能阻止草稿下载，也不能把整小节标为错误。

**验收**：用户可区分“数字识别分低”与“该拍仍不确定”；已解决项退出待处理列表；每个待处理项可直接打开来源，避免一小节多个重复笼统提示。

### F06 自动生成与下载草稿（P0）

- 有可用识别内容后自动准备 GP5 草稿，主界面提供一个清晰的默认下载入口。
- 草稿保留已知内容和具体问题标记，附带问题清单；普通低分和未逐小节确认不构成阻断条件。
- 不确定候选若写入草稿，应明确标为候选；无法表达的内容不能悄悄替换为确定音符。
- 为满足 GP5 文件结构确需占位时，明确标为“缺失 / 未识别占位”，并说明占位不代表真实休止或正确节奏。不能把占位计入成功识别。
- 局部无法编码时优先提供包含可用内容的草稿；完全没有可用音符或文件无法合法写出时，说明具体原因并提供诊断信息，不能仅显示灰色按钮。
- “草稿”“校验通过”“用户已核对”状态分开；严格导出可保留为次级入口。

**验收**：低 OCR 分、未核对小节和少量疑点均可下载草稿；文件经写出后重新读取验证，并在 Guitar Pro 中抽查打开、播放；缺失项和候选清单与文件标记一致。

### F07 人工修改与结果保护（P0）

- 保存识别原始结果、自动修订和人工修改的来源及时间，重新识别生成独立版本。
- 人工修改项默认受保护；自动流程可以提供建议，不静默覆盖。
- 对整小节未知的旧式人工核对状态采取保守保护，不能借升级自动取消。
- 刷新 / 重启后恢复已保存项目；失败任务可以重试并复用有效中间结果。
- 用户在外部 Guitar Pro 中修改的文件保留独立，不声称系统已同步这些修正。

**验收**：先改一个品位及一个时值，再重识别、补读、刷新和重启，已保存修改仍保留；可查看和下载旧草稿；中断不会损坏原始素材或原有结果。

### F08 简洁界面与进度（P0）

- 以准备素材、自动识谱、结果校对分阶段组织，桌面使用多区域布局，不仅依靠折叠隐藏单列内容。
- 使用低饱和色彩、清晰排版与留白；谱面预览和来源对照占据主要空间。
- 默认呈现导入、区域 / 类型确认、开始、进度、结果摘要和草稿下载。
- 说明、详细日志、参数、模型配置和高级修复默认折叠。
- 校对按疑点或小节选择，一次呈现一个小节；提供上一个 / 下一个疑点导航，不强制全曲展开。
- 进度显示当前阶段、已处理数量、待复核数量；取消后保留已保存结果，允许继续或重试。
- 长任务不能造成拖拽、页面滚动和取消按钮长期无响应。

**验收**：不打开高级区也可走完默认流程；无需逐小节确认可下载；失败信息说明下一步；任务处理过程中主要页面操作仍响应。

### F09 速度与本机运行（P1）

- 缓存按素材内容、裁剪、谱面类型、算法 / 模型及影响结果的设置失效，避免复用错误结果。
- 限制并发和模型重试；相同疑点不无条件重复调用。
- 记录各阶段耗时、缓存命中与模型调用量；优化前后在同一机器、相同输入和配置下比较。
- 保留后台启动、停止、端口提示、依赖检查及清晰错误日志。

**验收**：同设置重复识别复用有效缓存；修改相关设置后重新计算；程序报告实际阶段与耗时。绝对耗时目标待建立本机基准后确定，不先承诺固定分钟数。

### F10 安装、发布与版权（P1）

- README 提供环境准备、安装、启动、默认流程、模型可选配置、下载说明和常见问题。
- 保留上游来源、许可证、原功能和新增功能的区分。
- 沿用现有许可文件中非商业条款的适用范围，保留上游及既有授权，不扩大解释为所有代码均可撤回原许可。
- 明确软件许可与视频 / 曲谱版权不同；转谱不自动取得传播或销售授权。
- 代码版本可回退，升级前保护本地项目；公开仓库和发布包不包含个人素材、生成谱、密钥和运行缓存。

**验收**：按 README 在目标 Windows 环境完成安装启动；发布内容检查不带个人数据；可切回前一稳定代码版本，已有项目不被删除。

## 8. 结果与状态设计

任务状态建议为：待确认输入 → 整理谱面 → 识别 → 自动复核 → 草稿就绪。失败、取消和部分完成分别显示，不使用一个“失败”覆盖所有情况。

草稿就绪后同时显示三个独立维度：

| 维度 | 含义 |
| --- | --- |
| 文件状态 | 是否已生成、是否可下载、对应哪个结果版本 |
| 内容状态 | 已识别数量、疑点数量、缺失 / 占位数量 |
| 核对状态 | 哪些内容经过用户核对，哪些仅通过程序检查 |

最小结果记录应包含：素材和参数版本、谱行 / 小节来源、印刷编号与内部标识、拍位与候选、证据、疑点、自动修订记录、人工保护状态、导出版本。具体字段和存储实现由开发设计确定。

## 9. 质量验证与指标

### 9.1 评测材料

建立有使用权限的本地样本集，至少包含纯 TAB、联合谱、跨行拼接、边缘截断、两位数品位、延音线、八分 / 十六分、休止和重复视频画面。划分调试样本与未参与调试的验收样本，不能只用已调通的一首曲子证明泛化效果。

用户已手动修改的谱只有在主动提供为参考时才纳入对照；原文件保持独立，不自动覆盖或上传。公开测试使用可公开的自制 / 授权样例。

### 9.2 记录指标

| 指标 | 记录方式与用途 |
| --- | --- |
| 人工操作量 | 从区域 / 类型确认至草稿下载的额外点击数、修复操作数 |
| 人工校对量 | 每 100 小节实际需修改的拍位数及校对用时 |
| 读取质量 | 分别统计弦号 / 品位、时值、休止、延音错误，避免只看总拍数 |
| 内容完整性 | 缺失、重复、错拼小节及占位数量；占位不算识别成功 |
| 疑点有效性 | 标记中实际有错的比例，以及未被标记却有错的数量 |
| 自动修复质量 | 修复正确、无改善、引入新错分别统计 |
| 运行效率 | 总耗时、各阶段耗时、缓存复用、模型调用 / 超时数量 |
| 数据保护 | 人工修改被覆盖、原文件损坏或丢失的次数 |

### 9.3 下一阶段发布门槛

以下作为本 PRD 提议的验收规则；准确率和耗时的具体数值须完成基准测量后补充，不视为已与用户确认的百分比承诺。

- 默认流程只需前置确认与一次开始；无需手动调用结构修复、补读和模型复核才能结束任务。
- 有合法可用识别内容时，可下载草稿；低分或未人工核对不得单独阻断。
- 确定内容保留、疑点可定位；不以虚构休止 / 音符伪装完整识别。
- 保护人工修改与原文件，验证用例中不允许静默覆盖。
- 纯 TAB、联合谱均通过原有公开回归检查及本阶段新增的关键样例。
- 在同一验收样本集上，人工修复步骤减少；自动修改引入的新错必须单独复核，不能以提示变少代替质量提高。
- 导出文件通过重新读取验证，并在 Guitar Pro 中进行实际核对。

## 10. 实施顺序

| 阶段 | 交付重点 | 完成依据 |
| --- | --- | --- |
| A：基准与保护 | 固定现有版本；收集授权样例；定义疑点、来源和人工修改保护 | 可重复评测、旧结果安全、问题有定位 |
| B：自动流程 | 串联整理、识别、校验、补读及有界复核；自动准备草稿 | 一次开始后可结束并下载，无需高级修复操作 |
| C：减少真实错误 | 优先处理跨小节延音、两位数品位、遮挡误判休止及符尾关联 | 调试与独立验收样例均记录改善及新错 |
| D：体验与效率 | 疑点导航、取消 / 重试、缓存和耗时反馈 | 人工操作减少，本机重复处理可复用 |
| E：发布整理 | README、版本说明、安装验证、许可与隐私检查 | 可安装、可回退、无个人材料外发 |

先完成 P0，再安排 P1。P2 候选包括更多弦数与乐器、更广泛谱面、外部 GP5 修改导入、直接写出其他格式和更易安装的发行方式；这些不纳入近期验收。

## 11. 依赖、风险与待验证项

- PDF 或视频若从未出现完整音符，程序可能无法恢复真实内容；需要标缺失，不无条件重试。
- 五线谱与 TAB 的横向排版可能不严格对应；应保留关联证据和局部冲突。
- 视觉模型可能输出格式正确但音乐内容错误；不能以格式或拍数校验代替图像证据。
- 本地模型耗时和内存受硬件影响；自动化不能等同于对整曲无限调用模型。
- 自动化带来的主要收益须通过操作量和人工修正量验证，不能只减少告警数量。
- 具体性能基准、支持的复杂演奏法清单和准确率目标留到样本评测后细化；不影响已确认的四弦贝斯与草稿优先方向。
