# 两种谱面分别识别（试用）

当前分支 `codex/combined-tab-wip` 保留原纯 TAB 读取器，新增独立的“五线谱＋TAB”读取器。尚未合并主分支；此前的识谱加速分支停留在 `a4d1784`，可继续使用或回退。

## 选择正确类型

| 谱面 | 读取方式 |
| --- | --- |
| 纯 TAB，节奏符干与符尾在 TAB 上 | 保留原本地读取规则、演奏符号处理和缓存 |
| 上方五线谱、下方 TAB，横向位置对应 | 新本地读取器从上方识别节奏、下方 OCR 弦号与品位；单独缓存 |
| 自动识别判断不准 | 在“谱面类型”中手动选择，然后更新谱行图片 |

默认“本地图像识谱优先”会按谱面类型分流；新读取器能在没有 Ollama 时运行。可选的“只使用视觉模型”会对联合谱逐小节发送完整五线谱与 TAB，模型仍可能漏音或误读，结果需要逐项检查。

## 现有项目如何更新

### 位置叠加与逐拍复核（新流程）

1. 选择一行，点击“查看识别位置叠加图”。该操作重新分析候选，不修改已保存乐谱。绿框为已关联，橙框为低置信候选，红框为具体未确定音符；蓝圈为检测到的音符头，紫圈为旧规则回退位置。点击图片可放大，展开下方列表查看具体小节与拍位。
2. 下方品位与上方音符按整小节顺序对应，符干不能被多个独立拍位重复使用。符尾同时检查相邻音符之间多处连接，保留局部短符尾证据。同一行至少两个高置信同字体样例可为弱读数提供一致性佐证；这不是人工确认或跨乐句复制音符。
3. 总拍数不匹配仅形成小节错误，不再自动将所有拍位标为时值未确定。真正未确定的拍位单独标记。
   新关联不能通过节奏检查、而旧图像规则能给出完整且时值确定的候选时，保留旧候选并显示紫色回退位置。此处只比较从原图读出的两种候选，不补音、不搜索时值来凑拍。
4. 行首、行末保留为结构化片段，写入识别结果的 `fragments`。行末编号有印刷锚点支持、每个品位均能匹配、拍数完整、无未确定拍位、最后一个数字未贴裁切边缘时，可作为候选小节保留并明确标注“右侧边界未检出”；不能满足条件的片段不伪装成完整小节。
5. “模型逐拍复核（保留其他音符）”只请求疑点拍位字段的修改，输入完整小节、含相邻小节的原行、能定位疑点时的局部放大图。编号、拍位数量和其他已确定字段不能被模型重写；修改不能增加结构错误或扩大拍数偏差。备份规则继续生效。原整小节视觉识别仍可从“只使用视觉模型”使用。

实际第12小节已验证11个拍位、全部三弦7品及其混合时值；第14小节在无右小节线时保留11个三弦3品拍位及开头延音。截掉第14小节末尾音符的反例仍保持片段，不会为凑拍自动补音。原第2、6、8、26～28、120小节和原纯TAB确认样例继续回归。

加入回退保护后的旧25行隔离复测：167个候选小节，32个小节涉及校验问题；编号缺口为14→16、43→45、89→91，诊断GP5包含27个占位小节。后续原视频补读结果见下一节；原项目保存的数据未被隔离复测覆盖。

### 从原视频补读占位小节（另存草稿）

适用于同一项目仍保留生成本份 PDF 的原视频帧、已选择完整五线谱＋TAB 区域的情况。只有 PDF 时，先用同一原视频建立项目并处理视频；不能用无关视频配合小节号拼接。

1. 完成联合谱本地识别后，点击 **从原视频补读占位小节（另存草稿）**。此操作使用全部已有视频帧建立有限数量的索引视图，处理当前草稿的占位小节，不依赖视觉模型或 API 密钥。
2. 程序按实际印刷小节号定位，至少两个锚点一致才建立索引；再要求两个其他已识别小节的音符与时值相符，防止混入另一份乐谱。转场和播放光标可能遮字，支持同一位置的中段、前段、后段视图比较。
3. 接缝保留音符头和数字残留，不再只按完整弦线的覆盖范围裁边。仅在可见音符头、TAB 残留和符尾支持下恢复接缝处的符干关联；同一行至少两个一致的已知音高可结合实际音符头和可见 TAB 弦号校验弱数字。冲突或证据不足时保留原值，不按拍号搜索、插入音符或休止。
4. 完成后点击 **下载原视频补读草稿 GP5**，可展开每个补读小节的原始画面。候选、输入快照、来源证据和导出文件分别保存在 `score/video-recovery/<版本>/`；原 `score.json` 和人工核对状态不被改写。再次运行另建版本。

本机这份谱的结果：原27个占位全部消除，得到连续170小节的诊断草稿。对27个目标小节逐拍检查了品位、弦号和时值，并将GP5二进制读回逐音符比较；原非目标小节保持不变。第22、52小节的延音沿用原本已读出的音符，在前一小节修复后不再连带占位。

这不是全曲准确率声明：仍有9个原有音高候选拍位保留未确定标记，诊断导出以 `CHECK PITCH` 显示，低置信小节继续标 `CHECK`。零占位不等于全部已核对，普通草稿与正式导出的严格校验没有放宽。速度和调弦沿用项目设置，不从视频时间估算小节号或速度。

本机117项整体回归通过，后续关联、候选保护、下载检查另行复核通过；前端构建通过。原纯TAB读取器未改，主分支及原加速分支保留。

本机Qwen3-VL 8B对第12小节单拍的隔离复核约20秒，没有给出可接受修改，程序保留原值。当前改进主要来自图像关联与同字体佐证，不能据此宣称模型已能自动修复所有疑点。

1. 刷新 8001 试用页面，选择“自动判断”或“五线谱＋TAB”。
2. 点击“更新谱行图片（保留校对）”。程序重新从原 PDF / 截图裁图，保留上方五线谱的符头、符尾和小节号。
3. 已有小节及其人工核对标记保留；跳过的片尾画面也保留跳过状态。更新前的乐谱、清单和旧图片可恢复。
4. 已核对但实际错误的内容不会被自动覆盖。选中对应行，点击“取消此行核对，允许重识别”，再开始识谱。
5. 先试少量谱行，再增加处理范围。旧错误内容在后续行时，需要取消其核对并将该行纳入重识别范围；其他已核对行仍受保护。

### 修复跨行、编号和休止符

点击“修复跨行和编号并重识谱（先备份）”，会重新整理完整上下谱，按多个印刷小节号及前后行顺序校正编号，将能够对应到同一小节的行尾、下一行行首拼接。拼接原图会显示在谱行预览中。不会把不同编号的片段接在一起；后行已有完整版本时保留完整版本。

此操作对“本次识别前几行”范围内的联合谱重新识别，包括替换原有已核对内容，重置新结果的核对标记；其他行保留。原图、原乐谱及核对标记分别保存到项目 `score/backups/images-*/` 和 `score/backups/structure-*/`。所有原始行图仍保留。恢复时应先停止服务，再从同一次快照恢复 `manifest.json`、`score.json`，保留对应行图。

目前支持整小节休止、二分、四分、八分休止，并按横坐标与实际音符合并；括号品位从原图、增强图及二值图复读，仅与前一拍同弦同品匹配时视为延音。低置信数字会再从原图复读，仍不确定时保留未识别标记。没有补音或插入休止来凑拍。

新导入 PDF 或“读取当前视频截图”仍沿用原来的重建行为，会清空现有转谱数据；只更新裁图时请使用保留校对按钮。

## 已验证与限制

### 校验未通过时先下载诊断草稿

点击“下载诊断 GP5（保留低置信度音符）”即可把当前结果放到 Guitar Pro 中查看。已经读出音符候选、仅音高置信度不足的拍位照常导出，在小节标记中显示 `CHECK ... LOW CONFIDENCE`，具体不确定拍位附有 `CHECK PITCH` 文字。不会因单个低置信音符丢弃整小节；音符候选仍可能错误，原识别数据与未确定标记不变。

缺失、编号重复、未读出音符或时值错误的小节仍替换为带 `UNREADABLE BAR ... - PLACEHOLDER ONLY` 标记的占位休止。占位不是识别出的休止，不代表原曲，文件标题及文件名均明确标示不完整。完整导出校验不变；项目目录内的 `score-diagnostic.json` 记录占位原因及保留的低置信度拍位。

### 旧整小节模型修复的记录

下述为旧接口 `strategy=repair, local_review=false` 的记录。当前页面使用上方介绍的逐拍复核，不再请求模型重写整个小节；原接口仍保留兼容性。

先选择支持图片的模型（本机 Ollama 需保持运行），将“本次识别前几行”设为 1 试用，再点击“模型修复错误小节”。该入口会保存并备份当前乐谱，对所选范围内有未识别拍位、时值错误或编号间断的联合谱小节逐一复读。模型会收到放大的上下谱、原识别候选和校验错误；首次失败最多重试一次。每个小节的结果、失败原因会写入识谱日志。

该操作明确允许处理“已核对但仍有错误”的小节。备份保存在项目 `score/backups/model-repair-*/`，结构校验通过才替换对应小节，并取消该小节的人工核对标记；有效小节及失败小节保留原值。新结果也可能出现音符误读，结构校验不等于与原谱完全一致。草稿可在数据校验通过后下载到 Guitar Pro 核对。

只复核已有完整小节，不会自动补齐跨行残缺小节、修改编号或插入假休止来凑拍。编号间断仍可能阻止全曲导出。模型结果使用独立缓存，图像、候选、模型或接口变化会失效。此功能不改变纯 TAB 流程。

本机实际第 6 小节测试：`qwen3-vl:8b-instruct` 两次复读共约 116 秒，两次均只返回合计半个全音符的节奏，未通过 4/4 校验；程序保留原数据。新增流程能自动尝试修复，但此模型尚不足以可靠修复该素材全曲，不能承诺自动完成转谱。可在界面配置其他视觉服务后对同一小节比较效果。

- 真实素材验证了开头整小节休止、第 2 小节的 10 个音符与混合八分 / 十六分节奏、第 120 小节的 12 个音符及其节奏。逐一比较了弦号与品位，不只检查拍数。
- 原纯 TAB 的已确认 13 / 34 小节仍需作为回归样例保留；本次没有修改 `local_tab_reader.py`。
- 本地联合谱支持水平对齐、清晰的数字、常见实心音符、单双符尾及上述休止符。十六分等复杂休止、附点、半音符、复杂连音及演奏法仍可能需要修正。
- 拍号仍暂按 4/4；读不清的小节号会按上下文暂定并提示。不能把暂定值视为已从原图确认。
- 上一版结构修复的对照记录：从原 146 个候选增加到 165 个，新增 19 个跨行候选，其中 4 个通过现有数据校验；前 8 小节逐音符核对了拼回的第 8 小节与原第 4 小节的重复乐句一致，第 6 小节的括号延音、第 26～28 小节的休止与延音也已验证。
- 上述旧版对照有 39 个小节涉及校验错误，编号间断 4 处（13→16、43→45、76→78、89→91）。最新结果见上方新流程实测记录。部分拼接后拍数仍不足，原因需要逐个对照原图，不能单凭校验错误断定截图缺失。**仍不能直接作为全曲导出**；缺口不会自动编造填充。
- 本地结果与视觉结果均不会自动勾选人工核对。模型返回零个或多个小节时保留明确错误占位，防止失败小节被静默略过。

## 恢复或回退

试用工作目录仍是 `.release/recognition-speed/`，使用 `start.ps1 -Port 8001`。主分支和原 8000 服务不受影响。原识谱加速版可按 `docs/RECOGNITION_SPEED.md` 切回，切换后重新构建前端并启动服务。


### 识谱提醒的含义

新版不再把最低数字OCR分数显示为整小节正确率，也不因旧小节分数低而标整小节 `CHECK BAR`。

- `CHECK PITCH`：已有音高候选仍未确定，标在具体拍位。
- `CHECK OCR`：该拍位的数字读数偏弱，尚无五线谱音高佐证。通过同一行多个一致音符头核对的读数单独记录为已佐证，不伪造新的概率分数。
- 时值未确定、总拍数不完整、缺失小节仍保持严格校验；诊断占位原因照常保留。来源显示音符头与符尾关联或图像规则回退，不代表节奏已经人工确认。
- 旧识谱数据没有逐拍证据时，页面和导出JSON保留“最低OCR分数、无法定位”的说明，不据此认定整小节错误；旧低分也不会被自动抬高。新增导出才采用新标记，已下载的GP5文件不会自动改动。

这些改动不重新识谱、不覆盖已有人工修改或另存草稿；需要重新识别时仍由用户明确启动。人工核对后的普通OCR提醒消除，但尚未解决的结构错误仍阻止正式导出。
