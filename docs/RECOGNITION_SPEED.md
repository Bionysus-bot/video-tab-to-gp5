# 识谱加速试用与回退

本次修改只在 `codex/recognition-speed` 分支进行，基于稳定版 v0.1.1（提交 `2b3477c40a58553227122f289be74b991362d4ff`）。主分支保持原版本，不自动合并或替换正式发布包。

## 改动

- 本地 OCR 使用最多 4 个内部计算线程；逻辑处理器少于 4 个时按实际数量限制。未缩小识谱输入、减少核对步骤或更改品位与节奏规则。
- 在每个项目的 `score/cache/local-tab/` 中保存机器识谱结果，使用原图内容、调弦、整行元数据、起始小节编号、前一行音符上下文和识别程序 / 依赖 / 权重签名决定是否复用。
- 缓存有内容校验，损坏时重新识别；无法写入缓存不妨碍识谱。改变算法、依赖版本或 OCR 权重后，旧缓存不会继续复用。
- 缓存只用于本地优先模式中的本地读取。视觉模型结果不缓存，已核对行继续按原有保护规则保留。
- 页面提供“忽略缓存，重新识别未核对谱行”，日志显示每行用时、缓存命中数和总用时。缓存不会自动勾选人工核对。
- 修复原版曲线判断产生 NumPy 布尔标量、导致部分连奏滑音无法保存为 JSON 的问题；只转换标量类型，判断条件不变。
- 进度文件读写同步，Windows 文件短暂占用时重试；即使最后保存失败也释放任务占用状态，避免页面一直显示识谱中。
- 优化视频谱面框选：拖动时按动画帧更新新选框，松手后一次保存；按实际预览尺寸换算坐标，支持拖到画面外松手和 Esc 取消。框选下方可修改 X、Y、宽度和高度，点击“应用参数”或按 Enter 保存，参数使用原视频像素并限制在画面内。

## 试用

独立工作目录：`.release/recognition-speed/`。该目录是 Git 工作树，与原工作目录及主分支文件分开。

按根目录 README 安装、构建后，可在这个工作目录启动另一端口：

```powershell
powershell -ExecutionPolicy Bypass -File ./start.ps1 -Port 8001
```

打开 <http://127.0.0.1:8001/>。浏览器按端口分开保存最近项目，可以重新导入同一 PDF 做比较；不要在两个服务之间共用同一份可写项目目录。本机的原服务 <http://127.0.0.1:8000/> 保留，试用数据不覆盖原项目。

第一次识别会写入缓存；再次识别相同范围或从前几行增加到全曲时，可复用符合条件的谱行。前行改动会影响下一行延音上下文，此时会重新计算相关行。

## 回退

本机原服务仍在 8000，关闭试用页面后可直接继续使用原版。停止试用服务，在试用工作目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File ./stop.ps1
```

如需把试用工作目录本身退回稳定代码，可在停止服务、确认自己的改动已保存后运行：

```powershell
git switch --detach 2b3477c40a58553227122f289be74b991362d4ff
cd frontend
npm run build
cd ..
powershell -ExecutionPolicy Bypass -File ./start.ps1 -Port 8001
```

需要重建前端，因为构建产物不由 Git 跟踪。此操作不删除项目文件或优化分支，也不重写主分支历史。要回到优化版，停止服务后执行 `git switch codex/recognition-speed`，重新构建前端、启动服务。

## 本机整曲实测

Windows / Python 3.12，同一份 52 行有效谱面、163 小节、906 个音符，单独运行，无其他 OCR 测试竞争 CPU。时间为识谱任务耗时，不含 PDF 导入、前端加载和 GP5 导出。

| 场景 | 耗时 | 复用缓存 |
| --- | ---: | ---: |
| 稳定版，2 线程，复测 | 70.66 秒 | 0 行 |
| 优化版，最多 4 线程，首次处理 | 22.72 秒 | 0 行 |
| 优化版，强制重识别整曲 | 84.42 秒 | 0 行 |
| 优化版，最后修复后新进程重复相同输入 | 1.30 秒 | 52 行 |

对照结果的全部音符、时值及演奏属性与已有完整谱一致，导出的 GP5 二进制也逐字节一致。重复识别的测试进程没有初始化 OCR 引擎，验证缓存跨进程生效。20 项本机素材回归、33 项公开测试和前端构建通过。进度文件锁修复后，还验证了真实 HTTP 接口的首次识别、缓存复用、强制重识别、人工核对标记保留和草稿下载。

首次处理与强制重识别的耗时差异较大；目前不能据此保证线程调整会稳定缩短首次识谱时间。此分支仍为试验版，确定验证到的收益是相同输入重复识别时复用缓存。

稳定版首次测得 125.73 秒，波动较大；表中使用更快的复测值作比较。不同硬件、字体、视觉模型路径和后台负载可能得到不同速度，不能据此保证所有输入的提速比例。

## 验证范围

整曲对照使用本机已有的 52 个有效谱行、163 小节和 906 个音符，比较每个音符、时值及演奏属性和 GP5 二进制结果；用户素材和完整转谱不上传仓库。

公开测试覆盖缓存命中、原图 / 调弦 / 上下文 / 版本变化失效、强制重识别、损坏缓存、缓存写入失败、未识别拍位阻止导出，以及强制模式下保留人工核对。实际耗时受硬件和曲谱排版影响。

稳定版的完整接口基准在测试进程中单独做了布尔标量转换，以绕过原有 JSON 保存中断；没有改变 OCR 线程数、输入尺寸或音符判定。稳定版源码未修改。
